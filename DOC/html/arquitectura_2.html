Guía de Modificación para Archivos Extensos (Hotspots)

El sistema de RACK Designer funciona como una arquitectura reactiva unidireccional basada en un Store Central con Proxy ES6. Antes de editar archivos grandes como modals.js, style.css, topology.js o rack.js, revisa los diagramas e instrucciones de seguridad a continuación. ¡No rompas el ciclo de datos!

Mapeo de Flujos y Ciclos del Sistema

Este diagrama muestra cómo interactúa el usuario con la interfaz física o la topología y cómo la acción es procesada de forma centralizada por el Store. El Store intercepta el cambio con un Proxy ES6, lo guarda automáticamente en localStorage y notifica al orquestador global main.js para refrescar únicamente los componentes necesarios sin recargas directas de página.

Ciclo de Flujo Reactivo de RACK Designer 2

Este mapa ilustra el árbol de importación y dependencias lógicas. En un extremo tenemos los archivos base que no conocen al resto (utils.js, store.js y el catálogo de plantillas), seguidos por los componentes visuales de UI que consumen los servicios del store, y finalmente la estructura de vistas de index.html que ensambla todo.

Esqueleto HTML5 maestro de la aplicación. Define el contenedor CSS Grid principal (#app), los diálogos modales inyectados por JavaScript y los scripts que componen el sistema. Maneja la inicialización temprana de los temas oscuros/claros en el <head> para prevenir el parpadeo de pantalla (FOUC).

Hojas de Estilo y Visuales

🎨 css/style.css
919 LOC 53.8 KB ★ CSS Crítico
El cerebro de diseño global. Define los colores del datacenter, los estilos de layouts móviles con CSS Grid y Flexbox, y las reglas visuales complejas para cada faceplate de equipos (servidores con rejillas, leds parpadeantes, puertos RJ45 interactivos).
🚨 Guía de Modificación Segura
  • Variables del Tema: Toda modificación de colores debe realizarse en :root o en [data-theme="light"]. No uses colores planos con hexadecimal en selectores hijos.
  • Efecto Flipper: Las animaciones 3D de las tarjetas de los racks se controlan con la propiedad transform-style: preserve-3d y backface-visibility: hidden. Si alteras esto, el giro visual trasera/frontal fallará.
  • Vistas traseras: En el Modo Claro, el diseño estipula mantener la vista trasera de los racks con colores oscuros para mantener legibles los cables de colores.
📱 css/mobile-drag-drop.css
260 B Fallback
Contiene ajustes CSS mínimos requeridos por la librería de polyfill para simular el fantasma de arrastre (drag-image) en pantallas táctiles de iOS y Android.

Lógica de Control y Estado

🚀 js/main.js
412 LOC 16.3 KB Orquestador
Punto de entrada de JavaScript. Inicializa la topología, los modales globales y gestiona el enrutamiento de renders selectivos. Mapea la rueda del mouse y la pantalla táctil para mover (pan) y acercar (zoom) el plano físico y la topología, y carga dinámicamente el script de demostración de datos solo cuando es necesario.

Funciones Clave

  • init(): Carga inicial de UI y escuchas globales.
  • renderAll(event): Re-renderiza de forma inteligente según el evento del store.
  • initGlobalEvents(): Eventos de teclado (Ctrl+Z / Ctrl+Y), zoom y menú contextual.

Cuándo Modificar

  • Para agregar nuevos shortcuts globales del teclado.
  • Para registrar o cambiar las vistas principales (ej: vista 3D futura).
  • Para modular eventos globales de clicks en el fondo.
🗄️ js/store.js
300 LOC 10.4 KB Estado reactivo
El cerebro de datos del Datacenter. Implementa un Store central reactivo mediante ES6 Proxy. Cualquier asignación directa a propiedades del estado (ej: store.state.racks.push(...)) dispara la sincronización automática con localStorage y emite el evento de cambio global. Incluye un histórico de hasta 30 snapshots para Deshacer (Undo) / Rehacer (Redo).

API del Store

  • snapshot(): Guarda copia profunda de los datos actuales.
  • undo() / redo(): Viaje en el tiempo por el historial.
  • addDeviceToRack(template, rackId, slot, side): Valida espacio y agrega.
  • moveDevice(devId, rackId, slot, side): Mueve equipo con validación.

Estructura de Datos (State Schema)

  • rooms: ID, Nombre.
  • racks: ID, roomId, Nombre, Altura, Color, dispositivos[].
  • devices: Datos de red, consumo, tamaño U, credenciales.
  • connections: Cables de red, color, tipo, puertos src/dst.
🛠️ js/utils.js
66 LOC 2.1 KB Ayudantes
Funciones utilitarias libres de dependencias del DOM. Proporciona escape de HTML para evitar XSS, generador de IDs cryptográficos seguros tipo UUIDv4 abreviado, gestor dinámico de notificaciones flotantes toast y gestor de descargas de blobs JSON.
📊 js/demoData.js
10.1 KB Mock Data
Contiene el dataset pre-armado de prueba para la simulación inicial del Datacenter (Sala Principal con Racks de red, servidores cargados con IPs simuladas, conexiones de fibra activas y switches conectados). Se carga bajo demanda usando inyección de script dinámico para optimizar el arranque de la app.

Componentes de Interfaz y Gráficos

📁 js/ui/catalog.js
161 LOC 9.1 KB UI Panel
Gestiona la barra lateral de catálogo de equipos. Muestra los iconos de los componentes, filtra por categoría (Red, Servidor, Storage, Piso), y enlaza los eventos de arrastre HTML5 tradicionales vinculando los datos iniciales del equipo para pasárselos a los Racks. También controla los tabs de salas en la parte superior.
📁 js/ui/faceplates.js
222 LOC 8.7 KB UI Rendering
Factoría de visualización física de los equipos. Genera el código HTML/SVG inline que simula los componentes físicos de servidores (LCDs con IPs vivas, botones de encendido), switches (24 puertos RJ45 parpadeando que reaccionan si el switch está cableado), UPS (pantalla LCD de carga de batería) y la vista trasera del rack con sus tomas PDU.
📁 js/ui/rack.js
459 LOC 19.0 KB ★ UI Crítico
Controla la renderización física de los armarios Racks, ranuras por unidades de rack (slots), la animación de giro para ver la parte trasera (rear side) y los escuchadores de eventos para arrastrar y soltar (Drag & Drop) entre el catálogo y las ranuras disponibles del rack.
🚨 Guía de Modificación Segura
  • Sincronización al Girar: Cuando agregues un evento a las tarjetas físicas, recuerda que el giro destruye y vuelve a crear elementos en renderPhysical(). Debes conservar los IDs activos en el set flippedRacks para que un rack mantenga la vista trasera si el usuario lo giró previamente.
  • Cálculo de Espacio Libre (canPlace): Si planeas agregar validaciones personalizadas (por ejemplo, evitar montar un servidor de 200kg arriba de un rack por peso), debes programarlas en esta función auxiliar para prevenir que el D&D del navegador active el estado 'drop-invalid'.
📁 js/ui/topology.js
826 LOC 26.9 KB ★ Canvas Engine
El motor de topología de red gráfica. Rinde un plano gráfico completo dibujando salas, racks y equipos como nodos móviles usando el Canvas 2D de HTML5. Traza cables como curvas Bézier cúbicas con partículas de corriente que fluyen siguiendo el cable en tiempo real usando un bucle de animación optimizado (requestAnimationFrame).
🚨 Guía de Modificación Segura
  • Bucle de Dibujo (drawTopo()): Nunca agregues peticiones AJAX, cálculos del store pesados o lógica del DOM síncrona dentro de esta función, ya que se ejecuta a 60fps. Cualquier retraso bloqueará el scroll y zoom del mapa completo.
  • Cálculo de Colisiones de Cables: El doble clic para editar un cable se calcula en base a 30 muestras segmentadas a lo largo de la ecuación paramétrica del vector Bézier. Si cambias el trazado de los cables, asegúrate de actualizar la rutina de interpolación en el evento dblclick del canvas.
📁 js/ui/tables.js
256 LOC 12.1 KB UI Data Grid
Maneja el panel inferior de datos. Construye las tablas HTML del inventario y las conexiones físicas del Datacenter. Implementa la edición en celda rápida mediante doble clic con validación inmediata de campos especiales (como máscaras de IP y MAC) y enlaza la generación de archivos Excel (mediante la librería SheetJS) y exportador nativo de CSV.
📁 js/ui/modals.js
931 LOC 38.8 KB ★ Formularios e IO
El archivo de lógica de interfaz más extenso. Centraliza la validación, apertura y guardado de todos los formularios modales del sistema (añadir racks, configurar equipos, emparejar conexiones). Además, contiene la lógica matemática de exportación gráfica: renderiza la estructura de racks en caliente a un canvas oculto y lo descarga como imagen PNG, e implementa el Modo de Ubicación Rápida (Asistida) para instalar equipos sin necesidad de arrastrar.
🚨 Guía de Modificación Segura
  • Evitar Fuga de Campos del Formulario: Los formularios de añadir plantilla y editar equipo comparten los mismos campos del DOM (dev-name, dev-ip, etc.). Cuando implementes una pestaña o campo adicional, debes asegurar su limpieza/inicialización en openAddDeviceModal(), o los datos del equipo anterior se propagarán.
  • Peligro en Reducción de Rack: Al editar las propiedades de un rack existente, modals.js evalúa si la nueva altura deja equipos por fuera del límite. Si modificas las advertencias, podrías permitir que un equipo se guarde en una ranura inexistente, corrompiendo el bucle de dibujado en rack.js.

Script puente del service worker. Debe residir estrictamente en la raíz del proyecto para gozar de scope completo sobre la URL principal de la aplicación, importando toda la lógica interna desde la carpeta de servicios.
🕸️ js/service/service-worker.js
110 LOC 3.8 KB Cache Worker
Implementación real del service worker. Gestiona el ciclo de vida de caché (estrategia Cache First with Network Fallback). Cachea de forma asíncrona todos los assets de RACK Designer para permitir que la aplicación abra y funcione al 100% sin conexión a internet.
