Guía de Modificación para Archivos Extensos (Hotspots)

El sistema de RACK Designer funciona como una arquitectura reactiva unidireccional basada en un Store Central con Proxy ES6. Antes de editar archivos grandes como modals.js, style.css, topology.js o rack.js, revisa los diagramas e instrucciones de seguridad a continuación. ¡No rompas el ciclo de datos!

Mapeo de Flujos y Ciclos del Sistema

Este diagrama muestra cómo interactúa el usuario con la interfaz física o la topología y cómo la acción es procesada de forma centralizada por el Store. El Store intercepta el cambio con un Proxy ES6, lo guarda automáticamente en localStorage y notifica al orquestador global main.js para refrescar únicamente los componentes necesarios sin recargas directas de página.

Ciclo de Flujo Reactivo de RACK Designer 2

Este mapa ilustra el árbol de importación y dependencias lógicas. En un extremo tenemos los archivos base que no conocen al resto (utils.js, store.js y el catálogo de plantillas), seguidos por los componentes visuales de UI que consumen los servicios del store, y finalmente la estructura de vistas de index.html que ensambla todo.

Estructura Jerárquica y Dependencias Lógicas

Estructura de Directorios y Segmentación

Mantener una arquitectura modular y separada por directorios es fundamental para la escalabilidad y el mantenimiento. En este proyecto separamos estrictamente la lógica de estado global (store.js) de la lógica de interfaz de usuario e interacción humana (dentro de js/ui/).

Importancia de esta segmentación:
  • Colaboración Eficiente: Permite a los desarrolladores UI modificar archivos en js/ui/ sin temor a romper la persistencia o el modelo de datos maestro en store.js.
  • Mantenibilidad (Responsabilidad Única): Si falla el renderizado del Rack, se inspecciona directamente rack.js. Si el problema es arrastrar items, es catalog.js. Se evita el temido "código espagueti" o monolitos inmanejables.
  • Reutilización y Limpieza: Herramientas compartidas (IDs únicos, matemáticas, validación de IP) viven aisladas en utils.js, disponibles sin amarrarse a componentes visuales.

Hojas de Estilo y Visuales

🎨 css/style.css
919 LOC 53.8 KB ★ CSS Crítico
El cerebro de diseño global. Define los colores del datacenter, los estilos de layouts móviles con CSS Grid y Flexbox, y las reglas visuales complejas para cada faceplate de equipos (servidores con rejillas, leds parpadeantes, puertos RJ45 interactivos).
🚨 Guía de Modificación Segura
  • Variables del Tema: Toda modificación de colores debe realizarse en :root o en [data-theme="light"]. No uses colores planos con hexadecimal en selectores hijos.
  • Efecto Flipper: Las animaciones 3D de las tarjetas de los racks se controlan con la propiedad transform-style: preserve-3d y backface-visibility: hidden. Si alteras esto, el giro visual trasera/frontal fallará.
  • Vistas traseras: En el Modo Claro, el diseño estipula mantener la vista trasera de los racks con colores oscuros para mantener legibles los cables de colores.

Lógica de Control y Estado

🚀 js/main.js
397 LOC 16.8 KB Orquestador
Punto de entrada de JavaScript. Inicializa la topología, los modales globales y gestiona el enrutamiento de renders selectivos. Mapea la rueda del mouse y la pantalla táctil para mover (pan) y acercar (zoom) el plano físico y la topología, y carga dinámicamente el script de demostración de datos solo cuando es necesario.

Funciones Clave

  • init(): Carga inicial de UI y escuchas globales.
  • renderAll(event): Re-renderiza de forma inteligente según el evento del store.
  • initGlobalEvents(): Eventos de teclado (Ctrl+Z / Ctrl+Y), zoom y menú contextual.

Cuándo Modificar

  • Para agregar nuevos shortcuts globales del teclado.
  • Para registrar o cambiar las vistas principales (ej: vista 3D futura).
  • Para modular eventos globales de clicks en el fondo.
🗄️ js/store.js
270 LOC 10.2 KB Estado reactivo
El cerebro de datos del Datacenter. Implementa un Store central reactivo mediante ES6 Proxy. Cualquier asignación directa a propiedades del estado (ej: store.state.racks.push(...)) dispara la sincronización automática con localStorage y emite el evento de cambio global. Incluye un histórico de hasta 30 snapshots para Deshacer (Undo) / Rehacer (Redo).

API del Store

  • snapshot(): Guarda copia profunda de los datos actuales.
  • undo() / redo(): Viaje en el tiempo por el historial.
  • addDeviceToRack(template, rackId, slot, side): Valida espacio y agrega.
  • moveDevice(devId, rackId, slot, side): Mueve equipo con validación.

Estructura de Datos (State Schema)

  • rooms: ID, Nombre.
  • racks: ID, roomId, Nombre, Altura, Color, dispositivos[].
  • devices: Datos de red, consumo, tamaño U, credenciales.
  • connections: Cables de red, color, tipo, puertos src/dst.
🛠️ js/utils.js
61 LOC 2.1 KB Ayudantes
Funciones utilitarias libres de dependencias del DOM. Proporciona escape de HTML para evitar XSS, generador de IDs cryptográficos seguros tipo UUIDv4 abreviado, gestor dinámico de notificaciones flotantes toast y gestor de descargas de blobs JSON.
📊 js/demoData.js
127 LOC 9.9 KB Mock Data
Contiene el dataset pre-armado de prueba para la simulación inicial del Datacenter (Sala Principal con Racks de red, servidores cargados con IPs simuladas, conexiones de fibra activas y switches conectados). Se carga bajo demanda usando inyección de script dinámico para optimizar el arranque de la app.

Mejoras Funcionales de Interfaz

  • Atajos en Canvas Vacío: Lógica condicional que renderiza botones rápidos directos en view-physical-content cuando store.currentRacks está vacío.
  • Menú Contextual de Rack: La botonera rack-hdr-btns se refactorizó para agrupar las herramientas en un menú desplegable interactivo (rack-menu-toggle), asistido por un event listener global para auto-cierre.
🚨 Guía de Modificación Segura
  • Sincronización al Girar: Cuando agregues un evento a las tarjetas físicas, recuerda que el giro destruye y vuelve a crear elementos en renderPhysical(). Debes conservar los IDs activos en el set flippedRacks para que un rack mantenga la vista trasera si el usuario lo giró previamente.
  • Cálculo de Espacio Libre (canPlace): Si planeas agregar validaciones personalizadas (por ejemplo, evitar montar un servidor de 200kg arriba de un rack por peso), debes programarlas en esta función auxiliar para prevenir que el D&D del navegador active el estado 'drop-invalid'.
📁 js/ui/topology/
~750 LOC 26 KB ★ MVC Engine
